# AutoLabeler 重构规范文档集

> 创建日期：2026-05-13
> 目标：把 auto-yolo-label 从「强制顺序的单体桌面应用」重写成「模块解耦、企业级、可桌面可 Web」的项目

---

## 三份文档的关系

```
01-requirements.md   →  要做什么（系统是什么、每个模块的输入输出）
02-constraints.md    →  必须怎么做（10 条强制纪律 + 5 角度约束 + 验收标准）
03-progress-template.md → 边做边记录什么（每次 PR 必须更新的 3 份活文档）
```

## 重要：这是「重写」，不是「在旧代码上改」

- 旧代码（`core/`、`gui/workers/` 等）可以**借鉴**但不要直接复用
- 旧测试（约 124 个）可作参考样本，但新代码的测试要独立重写
- 旧的 `mapping.json` 格式向后兼容（保持字段含义，可以加新字段）
- 旧目录 `vals/` 改名为 `val/`，旧站点目录里的 `.autolabeler/inference_results/` 结构不变

---

## 开始前必须确认

1. 已读完三份文档至少一遍
2. 本机已搭好 `conda env yolo_new` (Python 3.11.14)
3. 已装好 `black` / `ruff` / `mypy` / `pytest` 工具链
4. 已克隆仓库并能跑通 `pytest tests/` 现有测试
5. 已和负责人对齐当前里程碑（M1 / M2 / M3）

## 有问题怎么办

| 问题类型 | 处理方式 |
|----------|----------|
| 文档某句看不懂 | 直接问负责人，不要自己脑补 |
| 文档某条约束做不到 | 走 02-constraints.md 第 11 节豁免流程 |
| 发现文档有错 | 提 PR 修复（文档也在版本管理内） |
| 发现需求与实际有冲突 | 不要私自变更，先问 |

**核心原则：宁可多问，不要私自决定。**
