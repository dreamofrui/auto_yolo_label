# AutoLabeler 用户使用手册

## 目录结构要求

### 站点文件夹结构

```
站点文件夹（如 A9950）/
├── CodeA/              # 类别/代码文件夹
│   ├── ProductA/       # 产品文件夹
│   │   ├── img1.jpg
│   │   ├── img1.xml    # 可选：已有VOC标注
│   │   └── ...
│   └── ProductB/
└── CodeB/
    └── ...
```

**注意点**：
- 站点文件夹名称任意（如 A9950）
- Code 文件夹名称即为**标注类别名称**（如 M1_SP_PI_P）
- 产品文件夹内直接存放图片，支持子目录结构
- 支持 `.jpg`、`.jpeg`、`.png`、`.bmp` 格式

---

## 一、扫描（建立图片索引）

### 操作步骤

1. 打开"扫描"页面
2. 点击"浏览..."选择**站点文件夹**（如 `A9950`）
3. 点击"开始扫描"

### 扫描完成后会生成

```
站点文件夹/.autolabeler/
├── mapping.json      # 图片映射文件
└── classes.txt       # 类别列表
```

### 注意事项

- 扫描会自动跳过隐藏文件夹（以 `.` 开头）
- 如果存在已有 XML 标注，会验证标签名是否与 Code 文件夹名称一致
- 不一致时会报错并停止扫描

---

## 二、抽样（抽取样本用于标注）

### 操作步骤

1. 打开"抽样"页面
2. **站点文件夹**：选择与扫描相同的站点文件夹
3. **输出文件夹**：选择用于存放训练数据的目录（如 `database`）
4. 配置抽样参数：
   - **抽样模式**：
     - `count` - 固定数量：每个产品抽取固定数量
     - `ratio` - 比例：按比例抽取
     - `mixed` - 混合：结合比例和数量范围
   - **抽样数量**：固定数量模式下的抽取数量（默认40）
   - **抽样比例**：比例模式下的抽取比例（默认0.3）
   - **全抽阈值**：图片数≤此值时全部抽取（默认35）
   - **训练集比例**：训练集占比（默认0.9）
5. 点击"开始抽样"

### 参数说明

| 参数 | 说明 | 默认值 | 范围 |
|------|------|--------|------|
| 抽样模式 | 选择抽样策略 | count | - |
| 抽样数量 | 固定数量模式下每个产品抽取数 | 40 | 1-1000 |
| 抽样比例 | 比例模式下抽取的比例 | 0.3 | 0.01-1.0 |
| 全抽阈值 | 小样本全部抽取的阈值 | 35 | 1-100 |
| 训练集比例 | 训练集占总样本的比例 | 0.9 | 0.5-0.99 |

### 抽样逻辑

**固定数量模式（count）**：
- 如果 `全抽阈值 > 抽样数量`，以全抽阈值为基准
- 产品图片数 ≤ 基准值：全部抽取
- 产品图片数 > 基准值：按基准值抽取

**示例**：抽样数量=20，全抽阈值=30
- 产品A有 50 张图片 → 抽取 30 张
- 产品B有 25 张图片 → 抽取 25 张（全部）
- 产品C有 100 张图片 → 抽取 30 张

### 注意事项

- 抽样会自动检测已有的 XML/TXT 标注文件
- XML 标注会自动转换为 YOLO TXT 格式
- 空的标注文件会被自动删除
- 已抽样的图片不会被重复抽样

### 输出结构

```
database/
├── images/
│   ├── train/       # 训练集图片
│   └── vals/        # 验证集图片
└── labels/
    ├── train/       # 训练集标注
    └── vals/        # 验证集标注
```

## 三、人工标注

### 操作步骤

1. 使用标注工具打开 `database/images/train` 和 `database/images/vals`
2. 对应的标注文件保存在 `database/labels/train` 和 `database/labels/vals`
3. YOLO TXT 格式：
   ```
   类别ID x_center y_center width height
   ```
   坐标为**归一化**值（0-1之间）

### 注意事项

- 类别ID 对应 `classes.txt` 中的顺序（从0开始）
- 确保坐标值在 0-1 之间
- 每行一个目标框

---

## 四、训练（YOLO模型训练）

### 操作步骤

1. 打开"训练"页面
2. **Data 目录**：选择抽样生成的 `database` 文件夹
3. **输出目录**：选择模型保存位置（如 `out_model`）
4. 配置训练参数：
   - **模型大小**：`n`(nano)、`s`(small)、`m`(medium)
   - **训练轮数**：建议 100-300
   - **图片尺寸**：640 或 1280
   - **批次大小**：-1 表示自动检测
   - **设备**：auto/cpu/0/1（GPU编号）
5. 点击"开始训练"

### 参数建议

| 参数 | 小目标场景 | 大目标场景 | 内存充足 |
|------|-----------|-----------|---------|
| 图片尺寸 | 1280 | 640 | 1280 |
| 模型大小 | s 或 m | n | m |
| 批次大小 | -1（自动） | -1 | 16-32 |

### 注意事项

- 训练会自动生成 `data.yaml` 配置文件
- 训练过程中可在日志窗口查看实时进度
- GPU 会自动检测，无 GPU 时使用 CPU
- 小目标建议增大图片尺寸到 1280

### 输出结果

```
out_model/
└── weights/
    ├── best.pt       # 最佳模型
    └── last.pt       # 最后一轮模型
```

## 五、推理（批量标注剩余图片）

### 操作步骤

1. 打开"推理"页面
2. **模型文件**：选择训练生成的 `best.pt`
3. **站点文件夹**：选择原始站点文件夹（与扫描时相同）
4. 配置推理参数：
   - **置信度阈值**：0.25（建议 0.15-0.5）
   - **IOU 阈值**：0.45
   - **批次大小**：-1（自动）或手动设置
   - **设备**：auto/cpu/0
5. 点击"开始推理"

### 推理逻辑

- 只对**未抽样**的图片进行推理
- 推理结果保存到独立的带时间戳目录：
  ```
  站点文件夹/.autolabeler/inference_results/run_YYYYMMDD_HHMMSS/
  ```
- 保留原始目录结构：`run_xxx/CodeA/ProductA/图片.txt`
- 推理**不会**标记图片为"已还原"，允许重新推理

### 参数调优建议

| 场景 | 置信度阈值 | 说明 |
|------|-----------|------|
| 漏检严重 | 0.15-0.2 | 降低阈值，提高召回率 |
| 误检严重 | 0.4-0.5 | 提高阈值，提高精确度 |
| 小目标 | 0.2-0.3 | 小目标置信度通常较低 |

### 注意事项

- 推理结果**不会**直接保存到原始图片位置
- 需要通过"还原"功能将标注复制到原位置
- 可以多次推理，选择不同结果进行还原

---

## 六、还原（将标注还原到原始位置）

### 操作步骤

#### 方式一：从 Database 还原（人工标注）

1. 打开"还原"页面
2. 选择 **Database 目录**来源
3. **Database 目录**：选择 `database` 文件夹
4. **站点文件夹**：选择原始站点文件夹
5. 点击"开始还原"

#### 方式二：从推理结果还原

1. 打开"还原"页面
2. 选择 **推理结果**来源
3. **站点文件夹**：选择原始站点文件夹
4. 点击"刷新"按钮，选择要还原的推理记录
5. 点击"开始还原"

### 还原逻辑

- Database 模式：还原 `database/labels/` 中的标注
- 推理结果模式：还原指定 `run_xxx/` 目录中的标注
- **已还原的文件会被跳过**，避免重复覆盖
- 还原后 mapping.json 中的 `restored` 标志会更新

### 注意事项

- 两种模式互不影响，各自还原各自来源的文件
- 还原前会检查目标文件是否已存在
- 已还原的数据再次点击还原会跳过（计入 skipped）

---

## 七、转换（YOLO → VOC格式）

### 操作步骤

1. 打开"转换"页面
2. **站点文件夹**：选择原始站点文件夹
3. **输出目录**：选择 VOC XML 保存位置（可选，默认保存在站点文件夹）
4. 点击"开始转换"

### 转换逻辑

- 扫描站点文件夹下所有 `.txt` 标注文件
- 转换为 VOC XML 格式
- 保留原始图片尺寸信息
- 坐标精度保留 6 位小数

## 常见问题

### 1. 扫描报错"标签不一致"

**原因**：已有 XML 文件中的标签名与 Code 文件夹名称不一致

**解决**：修改 XML 文件中的 `<name>` 标签，使其与 Code 文件夹名称一致

### 2. 抽样数量不对

**检查**：
- 查看"全抽阈值"是否大于"抽样数量"
- 小样本产品会被全部抽取

### 3. 训练报错 CUDA out of memory

**解决**：
- 将"批次大小"设置为较小值（如 8）
- 或将"设备"设置为 `cpu`

### 4. 推理结果为空

**检查**：
- 置信度阈值是否过高
- 模型是否训练了足够的轮数
- 图片类别是否在训练集中出现过

### 5. 还原时找不到记录

**检查**：
- 站点文件夹路径是否正确
- 是否选择了正确的站点文件夹（不是其父目录）
- 推理结果目录是否存在

### 6. 无法识别推理结果

**原因**：站点文件夹路径选择错误

**解决**：确保选择的路径包含 `.autolabeler/inference_results/` 目录

## 工作流程推荐

### 完整工作流

```
1. 扫描  →  建立图片索引
2. 抽样  →  抽取样本图片
3. 人工标注  →  标注样本
4. 训练  →  训练模型
5. 推理  →  批量标注剩余图片
6. 还原  →  将标注还原到原位置
```

### 增量迭代（推荐）

```
第一轮：
扫描 → 抽样(小样本) → 标注 → 训练 → 推理 → 还原

第二轮：
重新抽样(更多样本) → 标注(保留第一轮) → 训练 → 推理 → 还原

第三轮：
...
```

---

## 快捷操作提示

1. **抽样参数预设**：根据产品特点提前设置好常用参数
2. **模型版本管理**：不同训练轮数的模型保存到不同目录
3. **推理结果对比**：保留多次推理结果，对比后选择最佳版本还原
4. **备份 mapping.json**：映射文件记录了所有状态，建议定期备份
