# AutoLabeler 智能标注工具 - 产品需求文档

---

## 1. 项目概述

**目标**：开发桌面端智能标注工具，通过"少量人工标注 + 模型自动标注"方式，大幅降低标注工作量。

**用户**：算法工程师、数据标注人员

**核心价值**：
- 仅需人工标注 10%-20% 样本
- 模型自动标注剩余图片
- 标准化流程，减少错误

---

## 2. 术语定义

| 术语 | 说明 |
|------|------|
| 站点文件夹 | 最顶层目录：Code文件夹/产品文件夹/图片 |
| Code文件夹 | 一级子目录，名称即为标注类别 |
| 产品文件夹 | Code下的二级子目录 |
| mapping文件 | 记录所有图片状态与路径的索引 |

---

## 3. 数据结构

```
站点文件夹/
├── Code1/                    # Code名称 = 类别标签
│   └── ProductA/
│       ├── image001.jpg
│       └── image002.jpg
└── Code2/
    └── ProductB/
        └── ...
```

**特征**：
- 一个站点包含 1~N 个 Code 文件夹
- 不同 Code 下可有同名产品文件夹
- Code 文件夹名称 = 该类别的标签名

---

## 4. 功能需求

### 4.1 F1 - 数据扫描

扫描站点文件夹，建立全局索引。

**输入**：站点文件夹路径

**处理**：
1. 识别 Code/产品/图片 三级结构
2. 仅识别 .jpg/.jpeg/.png/.bmp 图片
3. 提取所有 Code 名称作为类别列表
4. 为每张图片生成唯一标识（编码文件名）
5. **[新增]** 如有XML标注文件，验证标签名与Code名一致

**输出**：mapping.json、classes.txt、统计报告

---

### 4.2 F2 - 样本抽取

从每个产品文件夹抽取样本，构建训练数据集。

**配置**：
- 抽样模式：count(固定数量) / ratio(比例)
- 固定数量：40张/产品
- 训练集比例：90%

**处理**：
1. 按配置规则确定抽取数量
2. **[新增]** 检测已有XML/TXT标注文件
3. **[新增]** 优先抽取已标注样本，全部抽取不计入限制
4. **[新增]** XML自动转换为YOLO TXT格式
5. **[新增]** 空标注文件自动删除
6. 生成编码文件名（Code__Product__ImageName.jpg）
7. 按比例分配到train/vals

**输出**：YOLO训练数据集（database/目录）

---

### 4.3 F3 - 人工标注

用户使用外部工具（LabelImg）标注抽样图片。

**操作**：
1. 加载 database/images/train 或 vals
2. 配置标签为 classes.txt 中的类别
3. 逐张标注，生成 .txt 文件
4. 保存到 database/labels/train 或 vals

**标注格式**（YOLO）：
```
<class_id> <x_center> <y_center> <width> <height>
```

---

### 4.4 F4 - 模型训练

使用标注数据训练YOLO模型。

**配置**：
- 训练轮次：100
- 批次大小：自动检测
- 图片尺寸：640
- 计算设备：自动检测

**处理**：
1. 校验数据完整性
2. 加载基础模型（yolo11m.pt）
3. 执行训练，显示进度
4. 自动保存最优模型

**输出**：best.pt、训练日志

---

### 4.5 F5 - 自动推理

使用训练好的模型标注剩余图片。

**配置**：
- 置信度阈值：0.25
- IoU阈值：0.45
- 批处理大小：自动检测

**处理**：
1. 读取mapping.json，筛选未抽样且未还原的图片
2. 加载模型
3. 批量推理
4. **[新增]** 推理结果保存到时间戳目录 `.autolabeler/inference_results/run_YYYYMMDD_HHMMSS/`
5. **[新增]** 保留原始目录结构
6. **[新增]** 生成 `inference_config.json` 记录参数
7. **[修改]** 推理后不标记 `inferred=True`（允许重新推理）

**输出**：
- 推理标注文件（.txt）
- 推理配置记录（inference_config.json）

---

### 4.6 F6 - 标注还原

将标注文件还原回原始目录结构。

**来源**：
- **Database目录**：还原人工标注结果
- **[新增] 推理结果**：从选中的历史推理run_xxx目录还原

**处理**：
1. 读取mapping.json
2. 遍历标注文件
3. 解析编码文件名，还原原始路径
4. 复制到原始图片同级目录
5. 更新mapping.json（标记restored=True，**从推理还原时同时标记inferred=True**）

**输出**：还原的.txt文件、更新mapping.json

---

### 4.7 F7 - 格式转换

将YOLO格式.txt转换为VOC格式.xml。

**处理**：
1. 遍历站点文件夹所有.txt文件
2. 读取对应图片获取尺寸
3. 坐标转换（归一化→像素）
4. 生成VOC XML文件
5. 删除原.txt文件

**输出**：.xml文件（不含XML声明行）

---

## 5. 工作流程

```
扫描 → 抽样 → 人工标注 → 训练 → 推理 → 还原 → (可选) 转换
```

---

## 6. mapping.json 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| original_relative | string | 原始相对路径 |
| code | string | Code名称 |
| product | string | 产品名称 |
| original_name | string | 原始文件名 |
| format | string | 文件格式（.jpg） |
| sampled | boolean | 是否已抽样 |
| split | string | train/vals/null |
| manual_labeled | boolean | 是否已人工标注 |
| inferred | boolean | 是否已自动推理 |
| restored | boolean | 是否已还原 |
| label_source | string | **[新增]** 标注来源 |

## 7. 界面需求

**整体布局**：
- 左侧：功能导航栏
- 右侧上：功能操作区
- 右侧下：日志输出区

**必需页面**：
| 页面 | 主要元素 |
|------|----------|
| 首页 | 项目概览、快速开始 |
| 扫描页 | 文件夹选择、扫描按钮、统计结果 |
| 抽样页 | 参数配置、抽样按钮、预览区 |
| 训练页 | 参数配置、开始/停止、训练状态 |
| 推理页 | 模型选择、开始按钮、**[新增]推理历史列表** |
| 还原页 | **[新增]来源选择**、还原按钮、校验结果 |
| 转换页 | 格式选择、转换按钮、结果统计 |
| 设置页 | 配置表单、保存/重置 |

**通用交互**：
- 耗时操作显示进度条
- 操作完成显示提示
- 危险操作需确认
- 实时滚动日志

---

## 8. 多次推理工作流

```
训练 → 推理1(conf:0.3) → 推理2(conf:0.2) → 还原(选择最佳)
         run_1200         run_1430          选择历史
```

**特点**：
- 支持无限次重新推理
- 保留所有历史记录
- 用户选择最佳结果还原
